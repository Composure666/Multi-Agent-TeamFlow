# Agent Run Debug Board Design

## Goal

把现有的 Agent Run 调试面板从“文字表格”改成更适合产品演示的流程展板。

## Experience Summary

用户从全局侧栏的 `分析` 入口进入页面，先看到所有会话的最近活跃状态。
选中某个会话后，中间区域显示该会话的 run 流程展板。
展板以“阶段节点”为主，不把每次工具调用都直接铺到主画布上。

## Layout

### Left Rail

- 复用现有会话导航
- 按最近活跃和状态展示
- 支持全局切换会话

### Center Canvas

- 只缩放中间画布
- 画布默认展示当前会话的主 run
- 当前 run 作为主流程展开
- 历史 run 收进下方折叠泳道
- 画布节点默认是阶段级：
  - 触发
  - 规划
  - 执行
  - 产出

### Right Drawer

- 点击节点后打开右侧详情抽屉
- 默认显示节点概览
- 可继续查看工具轨迹、原始 payload、关联消息和产物

## Interaction Rules

- 点击流程节点打开详情抽屉
- 画布支持缩放
- 实时运行时，当前节点和进行中的节点高亮
- 历史 run 默认折叠，点击后再展开
- 节点下钻优先在详情抽屉里完成，不在主画布堆太多工具级节点

## Entry Points

- 全局一级入口：侧栏 `分析`
- 快捷入口：当前会话 header 保留调试按钮

## Node Granularity

主画布只显示阶段节点，不直接展示所有 tool call。
工具调用、文件写入、bash、ask_user、report_task_result 等细节放在右侧抽屉和节点展开内容里。

## Visual Direction

- 产品感优先
- 画布像展板，不像日志表
- 信息层级以“会话 > run > 阶段 > 细节”为主

## Non-Goals

- 不把调试面板做成纯文本表格
- 不把所有工具调用都当作主画布节点
- 不改变现有数据契约
- 不新增调试数据模型
