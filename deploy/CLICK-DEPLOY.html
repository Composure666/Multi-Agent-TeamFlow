方式 B 的密钥版：彻底告别输密码（推荐，一次性设置）

密钥已经为你生成好了（C:\Users\he\.ssh\agenthub_lighthouse）。 只要把公钥装到服务器上一次，之后 scp / ssh 全程不再问密码 —— 也彻底绕开上面那个「密码打不进去」的毛病。

① 在网页终端里粘贴这一段（它会把公钥追加到服务器的 authorized_keys）：

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIJ5ZuyUnwHTawarBMgomjo/Imn4w5zu6Arilap6i5uo2 agenthub-lighthouse-deploy' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && wc -l ~/.ssh/authorized_keys

末尾会打印 1（或更多），说明写进去了。

② 回到本地，用带 -i 的命令传文件：

scp -i "C:\Users\he\.ssh\agenthub_lighthouse" -o IdentitiesOnly=yes "C:\Users\he\Documents\agenthub-deploy\agenthub-src.tar.gz" root@101.42.94.222:/root/
🔑
私钥保存在你本机 C:\Users\he\.ssh\agenthub_lighthouse，没有设密码短语（方便脚本调用）。 这个文件等于服务器的钥匙，别外传、别提交进 git。想更保险可以给它加个密码短语： ssh-keygen -p -f C:\Users\he\.ssh\agenthub_lighthouse（加了之后每次用都要输一次，脚本就不能自动跑了）。

⚠️ 在终端里敲 scp / ssh，密码提示处「字打不进去」
这是 Windows OpenSSH 的老毛病，跟服务器、跟你的操作都没关系。

根因：ssh/scp 要密码时，会把控制台从「处理输入模式」切成裸模式直接读键盘。 这个模式下 输入法（IME）的按键送不进去，而且控制台自己的一些快捷键也失效 —— 所以你敲了等于没敲，回车只发出一个空行。
另外还有一个经典陷阱：无回显。密码提示下本来就不显示任何字符（连 * 都没有）， 光标也不动 —— 很多人以为坏了，其实输进去了。

按顺序试，第 1 条通常就够了：
  1. 用「粘贴」代替「打字」（最有效）。 打开记事本把密码打出来 → Ctrl+A + Ctrl+C → 回到终端，在密码提示处 右键（或 Ctrl+Shift+V）粘贴 → 回车。 粘贴走的是另一条通道，绕开了裸模式的输入限制。
  2. 输入法切英文：按 Shift 或 Win + 空格。裸模式下中文输入法的按键会被吞掉。
  3. NumLock 按 3 下（奇数次，末态不变）。这是控制台的 NumLock 状态不同步 bug，触发一次重新同步。
  4. 换用传统控制台：Windows 设置 → 终端 → 把「默认终端应用程序」改成 Windows 控制台主机。 在 Win11 上 cmd 和 PowerShell 默认都由 Windows Terminal 托管，所以「换 cmd 也一样卡」是正常的，不是两个都坏了。
永久解法（一次性，之后 scp / ssh 全程免密）： 用 SSH 密钥。已为本机生成好一对密钥： C:\Users\he\.ssh\agenthub_lighthouse， 把它的公钥粘进服务器（见下方「方式 B 的密钥版」）。
